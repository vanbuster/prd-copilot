# evals — 用它自己的方法论测它自己

本目录是 prd-copilot 的回归评测集。设计原则只有三条：

1. **判定全部二值断言**（yes/no 可判），不打连续分——断言级一致率可测量，0-100 打分的漂移无法治理。约六成断言由 `scripts/check_structural.sh` 机判，其余由独立评审代理判（每条判定必须引用 PRD 原文为证据）。
2. **用例从真实失败中生长**。初始只有 3 个用例（主流程冒烟 / 历史 bug 回归 / 门禁防伪），预先想象的完备覆盖只会漂向作者自嗨。真实使用中"要大改"的输入，脱敏后收编为新用例。
3. **人工 ritual 触发，不建 CI 跑生成、不建定时任务。** 改完 skill 后手动跑：至少 C1 + 与改动相关的用例，全绿才算修复。

## 用例

| ID | 测什么 | 为什么是它 |
|---|---|---|
| [C1-thin-input](cases/C1-thin-input/) | 薄输入全流程冒烟：一句话进，完整 PRD 出 | 主路径 |
| [C4-ai-negative](cases/C4-ai-negative/) | AI 判定负例：满篇"智能"但核心是规则引擎 | 回归真实历史 bug（v1 曾用 40 关键词子串匹配，"智能排班"必误判） |
| [C8-redline-bait](cases/C8-redline-bait/) | 红线诱饵：输入本身塞满空洞表述 | 验证门禁真拦垃圾，还是把垃圾复读出来 |

每个用例 = `input.md`（输入原文 + 澄清作答脚本）+ `expected.md`（分层断言：L1 行为机判 / L2 门禁机判 / L3 质量评审判）。

## 怎么跑一轮

1. 新开会话，按 `input.md` 触发 skill，澄清按作答脚本回答。
2. 产出跑 `scripts/check_structural.sh <产出文件>` → L1/L2 结果。
3. 起独立评审代理（喂三样：产出 + `judge-prompt.md` + 对应用例 `expected.md` 的 L3 断言清单，**不喂生成过程**）→ L3 结果。
4. 结果记入 `runs/YYYY-MM-DD/results.md`（记 skill 版本 + 评审模型 + 逐断言结果），**原始产出一并入库，失败的 run 不删除、不策展**。
