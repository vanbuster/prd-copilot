## 1. 产品概述

### 1.1 名称与定位

**书接**是一款面向在校大学生的校园二手教材交易微信小程序，核心解决教材"学期末无处卖、开学季买不到便宜二手"的校内供需错配问题。

### 1.2 背景与问题

- 教材残值流失：一学期后闲置，只能按约 1 元/斤卖废品，人均每学期闲置 5-8 本，覆盖全体在校生。
  > 假设值，需验证：人均闲置数与回收价，需试点校抽样 100 人问卷核实。
- 渠道错配：闲鱼按物流设计，教材单价 10-30 元、运费占比高；校园墙无结构，按课程检索不可行。
- 时间窗错位：卖书高峰在期末（6/12 月），买书高峰在开学（9/2 月），中间 2 个月无承接机制。
- 为什么是现在：小程序免安装、学生微信渗透饱和，学号认证低成本建立同校信任。

### 1.3 核心价值主张

一句话：**让教材在同校学生间按课程精准流转，当面交易零运费。**

- 按课程匹配：书绑定课程代码检索，3 步定位教材——区别于闲鱼全文搜索
- 同校面交：零运费、当场验货——区别于跨城物流平台
- 时间窗托管：期末录入、开学自动放出——区别于即时信息墙

1. 选课公布需购 6 本（焦虑｜新书贵）

## 3. 用户故事与需求分析

### 3.1 核心用户故事

**P0**

- **US1**: As a 卖家, I want 扫 ISBN 自动带出书目并发布, So that 2 分钟内挂出一本书
  - [ ] 正常路径：扫码自动填书名/版次，补价格成色后发布成功
  - [ ] 边界条件：库无此书转手动录入并打标
  - [ ] 异常路径：摄像头权限被拒，展示手动入口与开启引导
- **US2**: As a 买家, I want 按课程代码检索在售教材, So that 定位本学期课程对应的书
  - [ ] 正常路径：输课程代码返回绑定的在售书列表
  - [ ] 边界条件：无在售书展示空状态+到货订阅入口
  - [ ] 异常路径：检索超 3s 提示重试并降级为关键词搜索
- **US3**: As a 买家, I want 站内私信约面交, So that 不加微信完成沟通
  - [ ] 正常路径：消息发出，对方收到订阅提醒
  - [ ] 边界条件：对方 48h 未回复提示"卖家近期不活跃"
  - [ ] 异常路径：含站外导流内容（二维码/手机号）时拦截并说明
- **US4**: As a 交易双方, I want 面交后双方确认完成, So that 成交被记录并计入信用分
  - [ ] 正常路径：双确认后订单变"已售出"
  - [ ] 边界条件：单方确认 72h 后自动完成并通知另一方
  - [ ] 异常路径：点"交易失败"进争议态，书回在售

**P1**

- **US5**: As a 卖家, I want 管理四态书单, So that 期末批量挂单后统一跟进
  - [ ] 正常路径：四态列表可查看、改价、下架
  - [ ] 边界条件：空书单展示发布引导
  - [ ] 异常路径：改价失败保留草稿并提示重试
- **US6**: As a 买家, I want 订阅课程到货提醒, So that 到货第一时间知道
  - [ ] 正常路径：新书上架 10 分钟内推送提醒
  - [ ] 边界条件：同课程每日最多 1 条，去重合并
  - [ ] 异常路径：订阅授权关闭时站内消息中心兜底
- **US7**: As a 用户, I want 查看对方信用分与评价, So that 决定是否与其交易
  - [ ] 正常路径：详情页展示信用分、成交数、近 3 条评价
  - [ ] 边界条件：新用户展示"新用户"标识而非 0 分
  - [ ] 异常路径：加载失败展示占位并可重试

**P2**

- **US8**: As a 卖家, I want 开学季定时上架, So that 期末录入的书开学自动放出
  - [ ] 正常路径：到期自动转在售并通知卖家
  - [ ] 边界条件：定时前可改期或立即上架
  - [ ] 异常路径：失败重试 3 次，仍失败通知卖家手动处理

## 4. 功能需求

### 4.1 书籍发布与管理（关联 US1/US5/US8）

模块目标：卖家 2 分钟完成结构化挂单。

| 编号 | 功能点 | 触发条件 | 预期行为 | MoSCoW | 验收标准 |
|---|---|---|---|---|---|
| F1 | 扫码发布 | 点"卖书"授权摄像头 | 成功自动填书目；库无记录转手动录入 | Must | 常见教材带出率 ≥90% |
| F2 | 书单管理 | 进"我的书摊" | 四态列表，可改价/下架/编辑 | Must | 变更即时生效 |

- 边界：含单本创建/编辑/下架；不含批量导入。F1 依赖第三方 ISBN 库。
- 业务规则——书籍状态流转表：

| 当前状态 | 事件 | 下一状态 |
|---|---|---|
| 在售 | 买家预订且卖家接受 | 已预订 |
| 已预订 | 双方确认完成 | 已售出 |
| 已预订 | 争议或 7 天未面交 | 在售 |
| 在售 | 卖家下架 | 已下架 |

- 定价参考公式：建议价 = 新书定价 × 成色系数（全新 0.5/九成新 0.4/七成新 0.3），卖家可改。

| 峰值并发 | 500 并发错误率 <0.5% | 开学季压测 | 无状态服务+自动扩容 |

### 5.2 可用性

可用性 99.5%（全年停机 ≤2628 分钟），开学季 2 周提级 99.9%（窗口停机 ≤20 分钟）；每日全量+增量备份；RTO ≤4h，RPO ≤15min。

### 5.3 安全

- 微信 OpenID 绑定学号双因子，防冒用（OWASP A07 认证失效）
- 私信与联系方式仅交易双方可见，按用户鉴权（OWASP A01 访问控制）
- 全链路 HTTPS/TLS1.2+，学号加密存储（OWASP A02 加密失效）
- 发布与私信内容服务端过滤 XSS/注入（OWASP A03 注入）
- 个人信息最小必要收集，学号仅用于校园认证（合规）

### 5.4 兼容性

微信 ≥8.0.30，基础库 ≥2.30.0，iOS ≥13，Android ≥8.0。

### 5.5 可扩展性

3 个月 1 校 2000 人/1 万册；6 个月 3 校 8000 人/4 万册；1 年 10 校 3 万人/15 万册、图片约 300GB——对象存储配生命周期策略（已售 90 天转低频）。

## 6. 信息架构与交互流程

### 6.1 页面结构

- 首页（课程入口/搜索框/开学季专区）
  - 搜索结果页
  - 书籍详情页
- 卖书（扫码发布/手动录入）
- 消息（私信会话/到货与订单通知）
- 我的（我的书摊/我的订单/收藏/信用分/校园认证）

### 6.2 核心交互流程

**流程 A：卖家扫码发布（US1）**

1. 点"卖书"请求摄像头权限——异常：拒绝 → 手动录入入口+开启引导
2. 扫 ISBN 条码——异常：3 次识别失败 → 手动输入 ISBN
3. 查库带出书目——异常：库无此书 → 手动填写并打标
4. 填价格/成色/面交地点——异常：高于新书定价 → 二次确认弹窗
5. 提交发布——异常：审核不过（站外导流）→ 驳回并标明原因

**流程 B：买家从检索到成交（US2/US3/US4）**

1. 按课程代码搜索——异常：无结果 → 空状态+到货订阅
2. 进详情页看实拍图——异常：图片加载失败 → 占位图+重试
3. 点"我想要"预订并私信——异常：已被预订 → 推荐同课程其他书
4. 约面交时间地点——异常：卖家 48h 未响应 → 释放预订提示换卖家
5. 面交双确认——异常：单方 72h 自动完成；"交易失败"→ 争议态、书回在售

### 6.3 关键状态

- 空状态：搜索无结果 →"这门课还没人挂书，订阅到货提醒吧"
- 加载：骨架屏；超 3s 提示"网络较慢"+重试
- 错误：网络错误 toast+重试；业务错误给可执行操作（如"去认证"）
- 成功：发布成功 → 引导"再发一本"或"分享到课程群"

## 8. 不做什么

| 不做的功能 | 排除原因 | 未来是否考虑 |
|---|---|---|
| 在线支付与担保交易 | 成本过高：支付资质与合规成本远超 MVP 验证所需 | 考虑，v2 视纠纷率 |
| 快递物流对接 | 与定位不符：同校面交是差异化，引入物流即与闲鱼同质化 | 跨校区扩张时评估 |
| 全品类二手 | 与定位不符：品类扩张稀释"按课程找书"心智 | 1 年后视品类天花板 |
| 个性化推荐算法 | 优先级不足：万册规模课程检索已覆盖主路径 | 多校规模化后 |
| 购物车与合并结算 | 优先级不足：无支付则无结算场景 | 随支付一起评估 |

## 9. 假设与约束

### 9.1 核心假设

| 假设 | 验证方式 | 不成立时的备选方案 |
