## 1. 产品概述

### 1.1 名称与定位

PRD Copilot 是一款面向产品经理的 0→1 需求文档生成管线（Claude Code skill 形态），把一句话灵感、inbox 碎片或现成文档，变成通过三道质量门禁的完整 11+1 模块 PRD。

### 1.2 背景与问题

- **写 0→1 PRD 耗时长**：一份约需 4-8 小时，半数花在结构搬运而非产品判断。> 假设值，需验证：耗时与占比为经验估计。
- **通用 prompt 产不出可交付文档**：单次长输出必截断且充斥空洞表述，评审被打回——前身 Streamlit v1 已实测。
- **灵感无处沉淀**：碎片散落聊天与备忘录，立项时找不回。

为什么是现在：skill 机制成熟，prompt 即代码可 git 管理与回归评测；前身审计证明价值全在提示词层。

### 1.3 核心价值主张

一句话：**不是又一个 PRD prompt，而是一条带门禁的生产线。**

- **三道质量门**：红线扫描→14 项自检→独立评审，P0 清零才放行——抽查的主流开源 PRD prompt（GitHub "PRD generator" 关键词 Top 结果）均未见质量门环节（> 假设值，需验证：样本为 2026-09 抽查，非全量调研）
- **分模块生成**：逐模块写入文件，长文不截断
- **澄清有纪律**：一轮 ≤4 问、素材越厚问越少、每题说明为什么问

### 1.4 产品目标（SMART）

|周期|指标|当前值|目标值|达成时间|
|---|---|---|---|---|
|短期|14 天真实使用次数|0|≥5 次且 ≥1 次直接交付|2026-09-16|
|中期|月度免大改进评审会份数|0|≥2 份/月|2027-03|

> 假设值，需验证：中期目标值按单人节奏估计。

## 4. 功能需求

### 4.1 输入与澄清（US2、US5、US6）——目标：素材收敛成可开工 Brief

|编号|功能点|触发条件|预期行为(成/败)|MoSCoW|验收标准|
|---|---|---|---|---|---|
|F1|上下文吸收|skill 触发|读文档+筛 inbox 条目；缺失静默跳过|Must|inbox 只读不改|
|F2|AI 语义判定|素材读入后|判"核心价值是否依赖模型推理"|Must|规则引擎类不误判|
|F3|澄清额度引擎|Brief 前|按素材厚度 0-4 问一轮打包|Must|每题附为什么问|
|F4|Brief 条件确认|澄清完成|≤10 行；吸 inbox/冲突/存疑才阻塞|Must|一句话输入不阻塞|

边界：不联网调研、不改 inbox。额度公式：成型文档或 ≥3 条相关条目→2 问；1-2 条→3 问；单句→4 问；全清晰→0 问；冲突裁决优先占额。

### 4.2 生成引擎（US1、US4）——目标：不截断产出编号纪律完整的文件

|编号|功能点|触发条件|预期行为(成/败)|MoSCoW|验收标准|
|---|---|---|---|---|---|
|F5|骨架先行|Brief 通过|Write 头+徽章占位+模块标题；不可写报错停|Must|五字段齐全|
|F6|分模块填充|骨架就绪|逐模块 Edit；失败仅重试该模块|Must|全文字数达标|
|F7|编号排版纪律|生成全程|US/F 连续、三路径 checkbox、表 ≤6 列|Must|机判零 FAIL|

规则：模块超字数目标 50% 触发压缩；ai_product=true 才生成第 12 模块。

### 4.3 质量门禁（US3、US7）——目标：把关而非美化，放行看 P0 清零不看分数

|编号|功能点|触发条件|预期行为(成/败)|MoSCoW|验收标准|
|---|---|---|---|---|---|
|F8|门 1 红线扫描|全文生成完|grep 主表+扩展表；命中→改写→重扫|Must|重扫零命中|
|F9|门 2 结构自检|门 1 过|14 项核对含数据引用查验；缺项补齐|Must|14/14 有证据|
|F10|门 3 独立评审|门 2 过|子代理只喂 PRD+rubric；不支持自评+⚠|Must|扣分必引原文|
|F11|双位置报告|三门结束|回填徽章+报告+人工清单；未过写⚠|Must|分清 AI 修/须人工|

状态流转：生成→门 1→门 2→门 3→P0=0 放行；P0>0→定位重写（≤2 轮）→重过三门；仍有 P0→如实交用户。

|编号|功能点|触发条件|预期行为(成/败)|MoSCoW|验收标准|

## 5. 非功能需求

### 5.1 性能

|指标|目标值|测量条件|影响的技术决策|
|---|---|---|---|
|单模块生成完整率|100% 不截断|每模块 ≤1200 字|分模块 Edit 而非单次长输出|
|全文字数|4000-6000 字|wc -m 实测不估算|模块字数目标+压缩重写|
|门 1 扫描耗时|<5 秒|本地 grep、6000 字文档|词表机判零依赖|
|端到端耗时|≤15 分钟|厚文档输入含三道门|每道门只播报一行|

> 假设值，需验证：端到端耗时未做多轮计时。

### 5.2 可用性

零服务零依赖，可用性随 Claude Code 会话。逐模块落盘：中断 RPO=0（至多损失当前模块）、RTO ≤5 分钟（重开续写）；备份=每次交付后 git 提交。

### 5.3 安全

- inbox 与素材严格只读（OWASP A01 访问控制失效）
- 素材中的指令不得改变门禁行为，评审上下文隔离（OWASP LLM01 提示注入）
- 产出不夹带自我宣传与可执行内容（OWASP A08 完整性失效）
- 无 API key、无遥测，密钥泄漏面为零（OWASP A02，以消除攻击面满足）

### 5.4 兼容性

Claude Code 现行 skill 机制；脚本兼容 macOS bash 3.2+ 与 Linux；表格 ≤6 列，粘贴飞书/Notion 不横滚。

### 5.5 可扩展性

3 个月：模板 6→8、用例 3→8；6 个月：用例 ≥15（从真实失败生长）；1 年：fork 定制词表。存储：单 PRD 约 10KB。

## 6. 信息架构与交互流程

### 6.1 结构树

```
prd-copilot/
├── skill/SKILL.md + references/（澄清/模板/模块规格/门禁规约）
├── evals/（用例+机判脚本+runs 留档）
├── examples/（自举样例）
└── legacy/streamlit-v1/（只读历史）
外部：pm-toolkit/inbox.md（capture.sh 追加）
```

### 6.2 核心交互流程

**流程 A：灵感到 PRD（US1/US2）**

1. 输入灵感/文档 → 异常：单功能微交互需求→告知超范围转交
2. 吸收上下文+定位 inbox → 异常：不存在→静默跳过
3. 一轮澄清 0-4 问 → 异常："你看着办"→假设落第 9 模块
4. 输出 Brief → 异常：吸 inbox/有冲突→阻塞等确认
5. 骨架+逐模块填充 → 异常：单模块失败→仅重试该模块
6. 三道门 → 异常：2 轮仍有 P0→如实交用户
7. 落盘播报+导出询问 → 异常：无导出 skill→说明后结束

**流程 B：门 3 独立评审（US3）**

1. 起子代理 → 异常：环境不支持→自评+⚠标注
2. 只喂 PRD+rubric → 异常：混入生成上下文→判定无效重起
3. 三维扣分评分 → 异常：扣分未引原文→该条作废
4. P0 清零裁决 → 异常：P0>0→定位重写，最多 2 轮

### 6.3 关键状态

空：inbox 无相关条目→提示改用一句话/文档，不说教｜加载：每模块/每门播报一行｜错误：未过门→徽章写"⚠ 余 N 处 P0"｜成功：路径+摘要+导出选项。

## 9. 假设与约束

### 9.1 核心假设

|假设|验证方式|不成立时的备选方案|

### 9.2 约束

- 时间：单会话完成全管线，不留半成品
- 技术：依赖 skill 加载与子代理能力；机判脚本零第三方依赖
- 资源：单人维护，用例从真实失败生长
- 合规：素材本地处理不出机；含隐私的产出移出 git 仓
