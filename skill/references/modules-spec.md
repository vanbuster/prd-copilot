# 11+1 模块逐条输出要求

> 每个模块有字数目标和必含子项，生成时逐条满足。
> 各模块字数目标指**正文有效内容**（不含表格符号/checkbox 标记）；机判口径是全文 UTF-8 `wc -m` 4000-9000，见 quality-gates 门 2 第 13 项。
> 排版纪律：表格列数 ≤6，单元格内不换行、不嵌套列表——宽表粘进飞书/Notion 会横向滚动。

## 全局写作规范

- 面向开发团队的专业产品语言；每个需求点具体到可直接拆为开发任务的粒度
- Markdown：一级模块 `## N. 模块名`，二级 `###`，列表 `-`，验收标准 `- [ ]`，表格用 Markdown 表格
- 用户故事 US1/US2…（As a / I want / So that 三段式）；功能点 F1/F2…（关联用户故事）
- 优先级 P0（必须）/P1（应该）/P2（可以）；功能用 MoSCoW（Must/Should/Could/Won't）
- 非功能需求全部量化：数字 + 单位 + 条件 + 影响的技术决策
- 交互流程每步含异常分支

## 1. 产品概述（400-600 字）

- **1.1 名称与定位**：无名则起名；一句话定位"XX 是一款面向 [目标用户] 的 [产品类型]，核心解决 [什么问题]"
- **1.2 背景与问题**：2-3 个具体痛点（每个 1-2 句 + 影响面：影响多少用户/收入）；为什么是现在（时机/技术/需求变化）；有数据则引用
- **1.3 核心价值主张**：一句话概括 + 3 个价值点（价值描述 + 对用户的意义 + 与竞品的差异）
- **1.4 产品目标（SMART）**：短期（3 个月）+ 中期（6 个月），每个含指标名、当前值、目标值、达成时间

## 2. 目标用户（300-500 字）

- **2.1 用户画像**：2-3 个，**每个画像一张竖卡**（`**画像：<名字>**` 加粗行 + 字段列表，不用标题层级——`###` 会与 2.1 同级，`####` 违反排版纪律），不用宽表。字段：姓名（虚构但真实）/年龄职业/核心痛点（可感知的具体问题）/使用动机（具体场景触发，不是"因为需要"）/使用频率预估（基于什么判断）/技术熟练度（影响什么设计决策）/典型一天
- **2.2 使用场景**：3-5 个，每个含**触发条件 + 用户行为 + 预期结果 + 成功标准**；标注 P0 主场景 / P1 次场景
- **2.3 用户旅程**：选 1 个核心场景，5-8 步从"发现问题"到"问题解决"，每步标注情绪和痛点

## 3. 用户故事与需求分析（500-800 字）

- **3.1 核心用户故事**：8-12 个，按 P0/P1/P2 分组，每个必须编号 + 三段式 + 验收标准三路径：
  ```
  - **US1**: As a [具体角色], I want [具体操作], So that [具体价值]
    - 验收标准：
      - [ ] 正常路径：[可验证条件]
      - [ ] 边界条件：[边界场景处理]
      - [ ] 异常路径：[出错时的处理]
  ```
- **3.2 需求优先级矩阵**：表格列 = 用户故事 / 用户价值（高中低）/ 实现复杂度（高中低）/ 优先级 / 依赖

## 4. 功能需求（800-1200 字）

按功能模块分组（3-5 个），每组：

- **模块目标**（一句话）+ **关联用户故事**（US 编号）
- 功能表：编号 F1… / 功能点（做什么）/ 触发条件 / 预期行为（含成功和失败）/ MoSCoW / 验收标准
- **边界说明**：包含什么 / 不包含什么 / 模块间依赖
- **业务规则**：权限判断、状态流转、计算公式等

## 5. 非功能需求（300-500 字）——全部量化

- **5.1 性能**：表格列 = 指标 / 目标值 / 测量条件 / 影响的技术决策（页面加载、API 响应 P95、并发、数据处理量）
- **5.2 可用性**：可用性 %（换算全年停机分钟）、备份频率、RTO、RPO
- **5.3 安全**：3-5 条具体要求（认证方式/加密标准/权限模型/合规），标注 OWASP 分类
- **5.4 兼容性**：浏览器/设备/系统最低版本号
- **5.5 可扩展性**：3 个月/6 个月/1 年用户与数据增长量级及存储影响

## 6. 信息架构与交互流程（400-600 字）

- **6.1 页面/模块结构**：缩进树
- **6.2 核心交互流程**：2-3 个，编号步骤，**每步含异常分支**，标注关联 US
- **6.3 关键状态**：空状态（引导文案）/加载（骨架屏+超时处理）/错误（错误码+可执行操作）/成功（下一步引导）

## 7. 评估指标（300-400 字）

- **7.1 北极星指标**：只有 1 个；说明为什么选它而非其他候选；目标值 + 统计周期
- **7.2 关键业务指标**：表格列 = 指标 / 定义（计算口径）/ 当前基线 / 目标值 / 统计周期 / 负责团队，≥3 行
- **7.3 数据埋点**：5-8 个事件，表格列 = 事件名 / 触发时机 / 关键属性 / 对应指标

## 8. 不做什么（200-300 字）——必须模块，不可选

表格：不做的功能 / 排除原因（优先级不足·成本过高·与定位不符）/ 未来是否考虑。**至少 3 项**。

## 9. 假设与约束（200-300 字）

- **9.1 核心假设**：表格 = 假设 / 验证方式 / 不成立时的备选方案。**至少 3 个**
- **9.2 约束**：时间 / 技术 / 资源 / 合规

## 10. 风险评估（200-300 字）

表格：风险 / 影响 / 概率 / 缓解措施 / 负责人。**至少 3 个**，每个都要有缓解措施。

## 11. 里程碑与发布计划（200-300 字）

- 阶段表：阶段（≥2 个）/ 时间 / 核心功能范围（US 编号）/ 交付标准 / 依赖
- **发布标准**：功能（P0 故事全过）/ 性能（非功能达标）/ 质量（无 P0/P1 bug）/ 埋点已部署 / 文档已更新

## 12. AI 专项（仅 AI 产品，判定见 SKILL.md 第 1 步）

- 模型能力边界（能做什么 / 明确不能做什么）
- Prompt 设计策略（系统提示词结构、上下文管理、few-shot 策略）
- 质量指标：准确率 / 幻觉率 / 拒答率的目标值与测量方法
- 降级策略（模型不可用/超时/低置信度时的兜底方案）
- 数据飞轮（用户反馈如何回流改进模型/提示词）
- 人机协作模式（哪些环节必须人工确认）
