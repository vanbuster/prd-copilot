# 三道质量门规约

> 生成物必须依次通过三道门，不过门重写，最多 2 轮。
> **放行条件是 P0 扣分项清零，不是分数达标**——分数只用于展示。

## 门 1 · 红线扫描（字面级，可 grep）

### 主表（8 条，绝对不允许出现）

| 红线 | 必须替换为 |
|---|---|
| "优化用户体验" | 优化什么指标，从多少到多少 |
| "提升性能" | 哪个操作，从多少 ms 到多少 ms |
| "简单易用" | 多少步完成什么操作 |
| "安全保障" | 用什么技术方案，防护什么威胁 |
| "合理的价格" | 具体定价策略和区间 |
| "后续优化" | 明确版本和迭代时间 |
| "根据实际情况调整" | 具体建议和范围 |
| "待定" / "TBD" | 建议值 + 假设条件 |

### 空洞形容词扩展表（同样 grep，命中即改写）

`高效` `稳定` `流畅` `无缝` `极致` `大幅提升` `显著改善` `全面优化`
`seamless` `robust` `user-friendly` `state-of-the-art`

> 例外：出现在引用/对比语境（如"竞品宣称'无缝'但实测…"）不算命中，由改写者判断后保留并加注。

### 伪量化（grep 抓不到，交给门 3 评审断言）

"提升 50%"这类**有数字但无基线、无测量条件**的表述，等同空洞。评审时逐一核对：
每个百分比/倍数必须能回答"从什么基线、在什么条件下测量"。

## 门 2 · 结构自检（14 项 checklist）

- [ ] 1. 每个用户故事有编号（US1…）和完整 As a / I want / So that
- [ ] 2. 每个用户故事含正常 + 边界 + 异常三路径验收标准
- [ ] 3. 每个功能点有编号（F1…）、触发条件、预期行为
- [ ] 4. 非功能需求全部量化（不是"快速"而是"≤ 2s"）且标注影响的技术决策
- [ ] 5. 交互流程 ≥2 个完整流程，每步有异常分支
- [ ] 6. "不做什么" ≥3 项
- [ ] 7. 假设 ≥3 个（含验证方式和备选方案）
- [ ] 8. 风险 ≥3 个且每个有缓解措施
- [ ] 9. 里程碑 ≥2 阶段，每阶段有明确交付标准
- [ ] 10. 北极星指标只有 1 个，有定义和目标值
- [ ] 11. 无门 1 红线表述（复查）
- [ ] 12. 所有业务规则和计算逻辑有明确描述（判定证据：至少 1 处状态流转表或计算公式）
- [ ] 13. 总字数 4000-6000 字（`wc -m` 实测，不估算）
- [ ] 14. **数据引用查验**：凡引用调研数据/行业数据/竞品数据处，有来源，或标注 `> 假设值，需验证：…`

## 门 3 · 独立评审

### 执行方式（不可妥协的部分）

1. **评审必须在独立上下文进行**：用 Agent/Task 工具起评审子代理，输入只有两样——PRD 全文 + 本节 rubric。**不给生成过程、不给对话历史。** 生成者自评的分数没有公信力。
2. 环境不支持子代理时：如实自评，但报告必须标注 `⚠ 自评模式，分数仅供参考`。
3. 每条扣分判定**必须引用 PRD 原文作为证据**（引用到模块+句子），无证据的判定无效。

### 评分 rubric（三维，0-100，扣分制）

**完整性**
- 必检 7 模块（概述/用户/故事/功能/非功能/架构/指标）缺一扣 15 【P0】
- 新增 4 模块（不做什么/假设/风险/里程碑）缺一扣 10 【P0】
- 子项缺失每处扣 3-5

**量化度**
- 空洞表述（含伪量化）每处扣 10 【P0】
- 性能指标缺测量条件每处扣 5
- 安全要求缺 OWASP 分类每处扣 3
- 数据引用无来源且无"假设值"标注，每处扣 5 【P0】

**可执行性**
- 功能点缺触发条件或预期行为，每处扣 5 【P0】
- 验收标准未覆盖三路径，每处扣 3
- 交互流程步骤缺异常分支，每处扣 3
- 假设无备选方案 / 风险无缓解措施，每处扣 5

### 裁决

- **放行 = 全部 P0 扣分项清零。** 分数高低不影响放行（一份 92 分但有 1 处 P0 的文档不放行；一份 84 分零 P0 的文档放行）。
- 不放行 → 按扣分项定位到具体模块重写 → 重新过三道门。最多 2 轮。
- 2 轮后仍有 P0：如实报告，交用户裁决。**不死循环，不谎报。**

## 报告格式

### 文首徽章（frontmatter 之后第一行）

```markdown
> 🛡 质量门通过 · 完整性 NN / 量化度 NN / 可执行性 NN · 红线 0 命中 · 自检 14/14 · 独立评审
```

（未通过时如实写：`> ⚠ 质量门未全过：余 N 处 P0，详见文末报告`）

### 文末完整报告

```markdown
## 附：质量门报告（YYYY-MM-DD）

| 维度 | 分数 | P0 扣分项 | 其他扣分项 |
|---|---|---|---|

| 可执行性 | NN | 0 | … |

```
