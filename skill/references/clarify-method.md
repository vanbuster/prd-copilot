# 澄清方法论

> 原则：澄清的边际价值随上下文积累递减。素材越厚，问题越少；信息全清晰，一个不问。

## 问题额度（硬上限 4，一轮打包）

| 素材厚度 | 额度上限 |
|---|---|
| 一句话灵感，无相关 inbox 条目 | 4 问 |
| 有 1-2 条相关 inbox 条目 | 3 问 |
| 有成型文档 或 ≥3 条相关 inbox 条目 | 2 问 |
| 信息全部清晰 | **0 问（直接跳过）** |

- 上限取 4 的原因是工具事实：AskUserQuestion 单次最多 4 题。**一轮出完全部问题，绝不搞第二轮追问**——"填一张短表"和"被连环审问"是两种体验。
- 行业模板需要用户选择时，占 1 问额度。
- 素材冲突裁决题（见下）**优先**占用额度。

## 问题维度（按优先级，已清晰的跳过）

0. **冲突裁决**（最高优先）：inbox 条目之间、或条目与用户输入矛盾时，把矛盾双方做成 single 选项让用户裁决。矛盾绝不静默吞掉。
1. **目标用户**：产品面向谁？
2. **核心场景**：用户在什么情况下使用？
3. **功能边界**：MVP 包含哪些核心功能？
4. **差异化**：和现有产品的区别是什么？
5. **成功标准**：如何衡量产品是否成功？

## 出题规则

- 每题给 3-4 个具体、有区分度的选项，基于用户描述合理推断
- **每题附一句"为什么问"**，放在题干前的括号里：
  `（决定非功能需求的量化基准）首发平台是？`
- 问题之间不重复；简洁明确
- 优先用 AskUserQuestion 工具（选项式交互，用户可用 Other 自由作答）

## single / multi 判定

逐个审视选项，问自己：**"用户能同时选 A 和 B 吗？"**

- 选了 A 还能选 B → multi
- 选了 A 就排除了 B → single

| 例子 | 判定 |
|---|---|
| 面向哪类用户（大学生+职场人可并存） | multi |
| 首发平台（只能先做一个） | single |
| MVP 核心功能（登录+支付同时要） | multi |
| 商业模式（免费增值 vs 纯付费互斥） | single |
| 冲突裁决题（二选一定方向） | single |

## 用户不配合时

接受"你看着办"/"随便"：用最合理假设继续，**每个假设必须落进 PRD 第 9 模块**
（假设与约束表：假设 / 验证方式 / 不成立时的备选方案），不许静默吞掉。
