# PRD Copilot 产品说明

## 一、产品定位

PRD Copilot 是一款面向产品经理和创业者的 AI 辅助工具，能够将一段自然语言描述的产品想法，自动转化为结构完整、指标量化、可直接用于开发评审的 PRD（产品需求文档）。

核心理念：**产品经理只需关注「想做什么」，AI 负责补全「怎么写」。**

---

## 二、解决的问题

| 痛点 | 现状 | PRD Copilot 的解法 |
|------|------|--------------------|
| 写 PRD 耗时 | 一份完整 PRD 需要 4-8 小时 | 5 分钟生成结构化大纲 |
| 模块遗漏 | 容易漏掉非功能需求或评估指标 | 7+1 模块全覆盖，AI 自动补全 |
| 表述空洞 | 充斥「优化体验」「提升性能」 | 质量红线机制，强制量化 |
| 格式不统一 | 每个人写法不同 | 统一的 Markdown 格式输出 |
| AI 产品特殊性 | 缺少模型能力边界、降级策略 | 自动检测并生成 AI 专项模块 |

---

## 三、核心功能

### 3.1 五步渐进式工作流

```
描述需求 → 澄清细节 → 生成 PRD → 精修内容 → 导出文档
```

**Step 1 — 描述需求**

用户在聊天界面中用自然语言描述产品想法，支持从一句话到详细描述的任意粒度。

**Step 2 — 智能澄清**

AI 自动分析用户输入中的缺失信息，生成 3-5 个关键问题：

- 每个问题提供 3-4 个选项，用户可直接选择或补充自定义答案
- 单选/多选由 AI 根据选项互斥性自动判断（如「首发平台」为单选，「核心功能」为多选）
- 涵盖目标用户、核心场景、功能边界、差异化、成功标准五个维度

**Step 3 — 生成 PRD**

基于用户输入 + 澄清回答，生成完整的 PRD 大纲，包含 7+1 个标准模块。

**Step 4 — 逐节精修**

用户可选择任意模块进行展开补充：
- 左侧导航栏选择模块
- 输入精修指令（如「补充更多用户故事」「细化性能指标」）
- AI 在保留已有内容的基础上定向扩展

**Step 5 — 导出文档**

一键导出标准 Markdown 格式的 PRD 文件，包含标题、生成时间戳和完整内容。

### 3.2 PRD 7+1 模块结构

| 序号 | 模块 | 内容 | 字数要求 |
|------|------|------|---------|
| 1 | 产品概述 | 名称定位、背景问题、核心价值、SMART 目标 | 300-500 字 |
| 2 | 目标用户 | 2-3 个用户画像、3-5 个使用场景 | 200-400 字 |
| 3 | 用户故事 | 6-10 条 As a / I want / So that 格式故事，P0/P1/P2 分级 | 400-600 字 |
| 4 | 功能需求 | 按模块分组，含功能描述 + MoSCoW 优先级 + 验收标准 | 500-800 字 |
| 5 | 非功能需求 | 性能、可用性、安全、兼容性（全部量化） | 200-400 字 |
| 6 | 信息架构 | 页面结构树、核心交互流程、状态说明 | 300-500 字 |
| 7 | 评估指标 | 北极星指标 + KPI 表格 + 埋点事件 | 200-300 字 |
| 8* | AI 专项 | 模型能力边界、Prompt 策略、准确率指标、降级方案 | 自动触发 |

> *第 8 模块仅在检测到用户描述涉及 AI/智能功能时自动激活。

### 3.3 质量控制机制

**质量红线** — 以下空洞表述会被严格禁止：

| 禁止表述 | 正确写法示例 |
|----------|------------|
| 「优化用户体验」 | 「将注册完成率从 45% 提升至 65%」 |
| 「提升性能」 | 「首页加载时间从 3.2s 降至 1.5s 以内」 |
| 「简单易用」 | 「新用户 3 步内完成首次发布」 |
| 「安全保障」 | 「采用 AES-256 加密传输，通过 OWASP Top 10 安全审计」 |
| 「合理的价格」 | 「基础版 ¥29/月，专业版 ¥99/月」 |

**生成自检** — AI 在输出前会逐条核验：用户故事格式完整、功能点有验收标准、非功能需求全部量化、交互流程至少 2 个、无空洞表述。

## 四、技术架构

### 4.1 技术选型

| 层级 | 技术 | 选择理由 |
|------|------|---------|
| 应用框架 | Streamlit | 内置聊天 UI + Markdown 渲染 + 文件下载，快速交付 |
| LLM 调用 | OpenAI Python SDK | 兼容 DeepSeek、OpenAI 等 API，切换零成本 |
| 模型策略 | DeepSeek V4 Flash / Pro | Flash 快速响应（澄清），Pro 高质量输出（生成/精修） |
| 样式 | 自定义 CSS | 深蓝 + 青绿配色，进度条、卡片、标签等定制组件 |

### 4.2 Prompt 工程架构

采用四层 Prompt 结构，由外到内：

```
Layer 1 — System Prompt：角色定义 + 输出规范 + 质量红线
Layer 2 — PRD 模板上下文：7+1 模块详细结构定义
Layer 3 — 对话历史：用户输入 + 澄清问答
Layer 4 — 任务指令：澄清 / 生成 / 精修三种模式
```

### 4.3 模型分层策略

| 任务 | 模型 | 理由 |
|------|------|------|
| 需求澄清 | Flash（快速模型） | 需要快速响应，对创造性要求低 |
| PRD 生成 | Pro（高质量模型） | 需要强推理能力，输出 2500-4500 字 |
| 逐节精修 | Pro（高质量模型） | 需理解上下文并定向扩展 |

## 五、设计决策与思考

### 决策一：多轮对话 > 一次性生成

参考 MetaGPT 的 SOP（标准操作流程）思想。分阶段、有质量关卡的流程比单次生成质量更高。澄清环节天然解决了「模糊输入处理」这一核心难题。

### 决策二：7+1 而非 10+ 模块

参考 OpenAI PM Lead Miqdad Jaffer 的 10 模块模板，精简为 7 个核心模块。2-4 小时可交付的 PRD 工具应聚焦于「刚好够用」，过度设计反而分散注意力。第 8 个 AI 专项模块是加分项——展示对 AI 产品 PRD 特殊性的理解。

### 决策三：选项驱动而非自由输入

澄清环节为每个问题提供 3-4 个具体选项，降低用户的认知负荷。同时保留自定义输入，兼顾灵活性。单选/多选由 AI 根据选项的互斥性自动判断。

### 决策四：质量红线作为系统级约束

将「禁止空洞表述」写入 System Prompt，而非仅作为建议。确保每次生成的 PRD 都符合可执行性标准。

## 六、使用指南

### 快速开始

```bash
git clone https://github.com/vanbuster/prd-copilot.git
cd prd-copilot
pip install -r requirements.txt
streamlit run app.py
```

首次打开时，在左侧 ⚙️ 设置面板中配置 API Key，支持 7 个提供商（DeepSeek / OpenAI / Claude / 智谱 / 千问 / 豆包 / 自定义）。

### 配置方式

**方式一（推荐）：页面内配置**

点击左侧 `>` 展开侧栏，选择提供商 → 填入 API Key → 点击"开始使用"。Key 仅保存在浏览器会话中，不上传任何服务器。

**方式二：环境变量**

在 `.env` 中配置（适合开发环境）：

```env
DEEPSEEK_API_KEY=your_key_here
```

### 模型切换

侧栏设置面板中可切换当前提供商的模型（如 DeepSeek V4 Flash ↔ DeepSeek R1）。
