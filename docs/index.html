三道质量门

"优化用户体验""提升性能""待定"——这类空洞表述在产出里一个都活不下来。

门 1 / GATE 1

红线扫描

8 条红线主表 + 空洞形容词扩展表，字面级可 grep。命中即定位改写为量化表述："简单易用"必须变成"N 步完成 X 操作"。

门 2 / GATE 2

结构自检 · 14 项

用户故事三路径验收、非功能全量化、流程步步有异常分支、数据引用必须有来源或"假设值"标注——编造数据过不了这道门。

门 3 / GATE 3

独立评审

评审跑在隔离的子代理里，只看产出、不看生成过程——生成者不许给自己打分。放行条件是 P0 扣分项清零，不是分数好看。

管线

澄清有纪律：一轮 ≤4 问、素材越厚问越少、信息全清晰则 0 问、每题告诉你为什么问。生成分模块写入，4000+ 字不截断。

你拿到的不只是一份文档

每份 PRD 文末自带「交付前需你人工确认的 N 处」清单——AI 自动修复的不占清单，上面只有必须由你接管的。你拿它去评审会时，清楚知道哪几处是 AI 的假设。自举 PRD 的真实清单节选：

  • §1.2 背景 — 写 PRD 耗时 4-8 小时为假设值：无调研来源，按团队实际抽样
  • §5.1 性能表 — 端到端 ≤15 分钟为假设值：需多轮实测计时
  • §7.1/§7.2 — 北极星与业务指标目标值为假设值：零基线，首月校准
  • §9.1 假设一 — "PM 愿意用终端"是最高风险假设：试用期到期须你裁决续废

多运行时 · 定制即改 Markdown

skill 本体是纯 markdown（SKILL.md + references/）。任何按 SKILL.md 协议热加载技能的 agent 运行时都能用：

# 通用技能池（DSH / QClaw 等读 ~/.agents/skills/ 的运行时） ln -s "$PWD/prd-copilot/skill" ~/.agents/skills/prd-copilot

想改红线词表、行业模板、放行标准？fork 后直接改 skill/references/ 里的对应文件——prompt 即代码，没有配置系统。改完质量门跑一遍 evals/。

为什么这里没有"在线生成"按钮——但有本地控制台

本项目的上一版就是 Web 应用（约 2000 行 Streamlit，保留在 legacy/，tag v1.0.0 可跑）。它的问题不是"是网页"，而是把提示词复制了一份进应用里——两份真相源必然漂移。所以云端在线生成不做；但如果你不想开终端，仓库里的 app/ 是一个本地控制台：浏览器聊天壳 + Claude Agent SDK 直接运行同一个 skill，澄清问题弹卡片、三道门进度逐行显示、产出右栏预览。它不含一行提示词。
